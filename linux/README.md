# Booting Linux on the function model

The standalone simulator (`a.out.nospike`, built with `make no_spike`; rv64: `make XLEN=64 no_spike` in a clean tree) boots a
flat DDR image: the boot stub at 0x0 jumps to 0x80000000 with `a1 = 0x83e00000`.

- `ttg.dts` (rv32) / `ttg64.dts` (rv64, `mmu-type = riscv,sv39`): devicetree for this platform (256 MiB RAM at 0x80000000,
  ns16550a UART at 0x10000000, polled; an ACLINT mtimer at 0x1fd0e000 with mtime at +0 and mtimecmp at +8; no PLIC; timebase 132 MHz).
- `rv64_min.fragment`: kernel config fragment for the rv64 build (see below).
- `mkimage.sh <dir> <out.bin> [rootfs.cpio]`: builds the image from `fw_jump.bin`, `Image` and the initramfs of a
  linux_rv32 / linux_rv64 directory: OpenSBI at 0x80000000, kernel at 0x80000000 + `KOFF` (default 0x400000; rv64:
  `KOFF=0x200000`), devicetree at 0x82200000 and 0x83e00000, initramfs at 0x84400000. `DTS=ttg64.dts` selects the rv64
  devicetree (default `ttg.dts`). `MEM=0x30000000` sets a larger RAM for big initramfs images (the SPEC ref images use
  `MEM=0x70000000`).

```bash
make no_spike
MEM=0x10000000 bash linux/mkimage.sh ~/personal/llm4trace/linux_rv32 /tmp/linux.bin
REF_UNBUF=1 ./a.out.nospike --image /tmp/linux.bin     # boots to "rv32 login:" in about 0.12 G instructions
```

Notes
- The timebase must stay around 132 MHz: `mtime` advances by one per executed instruction, and a faster timebase makes
  the tick handler (each rdtime is emulated by OpenSBI, about 340 instructions) outlast the tick period.
- `time` is not a hardware CSR here: S-mode `rdtime` traps and OpenSBI emulates it.
- A guest `poweroff` ends the simulation (SBI shutdown ecall from S mode).
- Verified: Linux 5.15.170 boots; the 12 SPECint2006 `test` programs run with matching output (libquantum differs only
  by CRLF line ends, astar by about 1e-4 in two numbers, within SPEC's tolerance).
- Debug options: `REF_PC_EVERY`, `REF_PC_RING`, `REF_TRAP_TRACE`, `REF_TRAP_EVERY`, `REF_UNBUF` (see the README).
- The console stays at the login prompt afterwards; use `REF_MAX_INSTS=<n>` to stop (the run ends with `Simulation Timeout`).

## rv64 (2026-11-11, merged to main 2026-11-12)

Buildroot 2024.02.9 in the Lima VM (`~/br64`: riscv64 GCC 13.3, glibc, ABI lp64 = soft float, kernel 5.15.170, OpenSBI 1.2): start from
`br13`'s `.config` with `BR2_RISCV_64`/`BR2_RISCV_ABI_LP64`, `BR2_ARCH="riscv64"`, `BR2_GCC_TARGET_ABI="lp64"`, the kernel config
generated by `make ARCH=riscv tinyconfig` + `rv64_min.fragment` (`merge_config.sh -m`, `olddefconfig`) and
`BR2_TARGET_OPENSBI_ADDITIONAL_VARIABLES="PLATFORM_RISCV_XLEN=64 PLATFORM_RISCV_ISA=rv64ima_zicsr_zifencei PLATFORM_RISCV_ABI=lp64"`.
The images are in `~/personal/AI-Huma-data/linux_rv64/` (`Image`, `fw_jump.bin`, `rootfs.cpio`).

```bash
KOFF=0x200000 DTS=ttg64.dts MEM=0x10000000 bash linux/mkimage.sh ~/personal/AI-Huma-data/linux_rv64 /tmp/linux64.bin
make clean && make XLEN=64 no_spike -j4               # the objects do not depend on XLEN: clean when switching
REF_UNBUF=1 ./a.out.nospike --image /tmp/linux64.bin  # boots to "rv64 login:" in about 1 s (fast path); with Spike: XLEN=64 OUT=build-spike64 scripts/build_spike.sh, then build-spike64/a.out ... --diff
```

OpenSBI's rv64 fw_jump jumps to 0x80200000 (kernel at offset 0x200000), the devicetree is passed at 0x82200000.

## rv64g (F/D, 2026-11-13)

Same Buildroot flow in `~/br64g` (Lima VM `rvbuild`): `BR2_RISCV_ISA_RVF/RVD`, `BR2_RISCV_ABI_LP64D` (hard-float glibc), no C; kernel config =
`rv64_min.fragment` with `CONFIG_FPU=y` (`~/rv64g_kernel.config`); OpenSBI `PLATFORM_RISCV_ISA=rv64imafd_zicsr_zifencei PLATFORM_RISCV_ABI=lp64d`.
Build with `HOSTCC=gcc-13 HOSTCXX=g++-13` (host-m4 does not build with the VM's gcc 15). `ttg64g.dts` = `ttg64.dts` with `riscv,isa = "rv64imafd"`.
The rootfs overlay (`~/ovl`) runs `/usr/bin/fptest` at boot: libm sin / sqrt / exp, printf of float / double, and 4 forked processes
that recompute a double result 20 times with `sched_yield` and must match the parent bit for bit (checks the FS / f-register context switch).
Images: `~/personal/AI-Huma-data/linux_rv64g/`. Needs the FP=1 build of the model (`make XLEN=64 no_spike LDFLAGS="-lz lib/softfloat/softfloat.a"`).

```bash
KOFF=0x200000 DTS=ttg64g.dts MEM=0x10000000 bash linux/mkimage.sh ~/personal/AI-Huma-data/linux_rv64g /tmp/linux64g.bin
REF_UNBUF=1 REF_MAX_INSTS=600000000 ./a.out.nospike --image /tmp/linux64g.bin    # OpenSBI: "Base ISA : rv64imafdb"; prints "fptest: PASS", then "rv64 login:"
```

## rv64gc (kernel + OpenSBI with C, 2026-11-13)

Same `~/br64g` tree with only the kernel and OpenSBI rebuilt for C: kernel config `~/rv64gc_kernel.config` = `rv64g_kernel.config` with
`CONFIG_RISCV_ISA_C=y`, `BR2_TARGET_OPENSBI_ADDITIONAL_VARIABLES="... PLATFORM_RISCV_ISA=rv64imafdc_zicsr_zifencei PLATFORM_RISCV_ABI=lp64d"`;
`make linux-dirclean opensbi-dirclean && make HOSTCC=gcc-13 HOSTCXX=g++-13` (the user space stays rv64g, which a core with C runs unchanged).
`ttg64gc.dts` = `ttg64g.dts` with `riscv,isa = "rv64imafdc"`. Images: `~/personal/AI-Huma-data/linux_rv64gc/`. Needs the `RVC=1` build of the model.

```bash
KOFF=0x200000 DTS=ttg64gc.dts MEM=0x10000000 bash linux/mkimage.sh ~/personal/AI-Huma-data/linux_rv64gc /tmp/linux64gc.bin
REF_UNBUF=1 REF_MAX_INSTS=1500000000 ./a.out.nospike --image /tmp/linux64gc.bin   # OpenSBI "Base ISA : rv64imafdcb", kernel "ISA extensions acdfim", "fptest: PASS", "rv64 login:"
```
Spike lockstep (`--diff` with the `RVC=1` Spike build) over the first 250 M instructions, through `rv64 login:`: 0 mismatches.
